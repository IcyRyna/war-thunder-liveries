# 仓库维护

作品按载具分类，放在 `works/aircraft/<作品>/` 或 `works/ground/<作品>/`。参考作品放在 `references/<分类>/<作品>/`，保留原作者和来源。

每件作品保留自己的版本线，标签继续使用 `works/<作品>/v<版本>`；参考包使用 `references/<作品>/<来源编号>`。移动目录不改发布标签或附件。


游戏包、设计源和大型工程放入 Release。文件清单与完整校验值记录在 `docs/catalog.json` 和 `docs/checksums/`。

## 评价与发布边界补充提案

以下补充待维护者审查；不会自动改变已发布作品、附件、版本号或既有评价。

- 分别记录“制作中的当前候选”和“仓库已发布版本”。本地出现更高版本号，不会自行使已发布版本过期，也不会授权上传候选。
- 评价绑定作品版本及被评价文件的 SHA-256。修改后的区域重新进入待评价；只有原字节保留且适用范围相同的部位，才可能明确引用原有局部认可。
- 首页展示标签、整套认可与局部认可分开保存。存在被否定部位时，经验提取必须保留该边界，不能用整体展示标签覆盖它。
- 结构化评价索引、人工可读索引和作品页应覆盖相同的已发布作品。缺少记录时补充“待评价”或已核实的历史事实，不推断新认可。
- 新作品与候选修改上传前，先展示具体预览、差异、文件清单和拟上传范围，取得对应审查决定。技术通过、目录整理和制作完成不等于美术认可或发布授权。
- 同版本替换只在维护者明确要求时进行；记录旧、新附件摘要与采用理由。通常保留旧版本，在本作品自己的版本线上发布。

从作品提炼 Skill 规则时，应同时链接到作品版本、被认可或否定的具体方面及可复查证据。保留反例，避免把一次成功扩大成跨车型通用规则。
